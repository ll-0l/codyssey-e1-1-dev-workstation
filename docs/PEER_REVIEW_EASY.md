### 1-1. 절대 경로랑 상대 경로가 뭐예요?

💬 "절대 경로랑 상대 경로 차이 설명해 주세요."

🗣️
> "경로는 파일이 어디 있는지 알려주는 **주소**예요.
> **절대 경로**는 맨 꼭대기 `/` 부터 시작하는 전체 주소라서, 제가 지금 어느 폴더에 있든 항상 같은 파일을 가리켜요. 주소로 치면 '서울시 ○○구 ○○로 12' 같은 거죠.
> **상대 경로**는 '지금 내가 있는 곳 기준'으로 말하는 주소예요. '여기서 옆 건물' 같은 느낌이요. 점 하나 `.` 는 지금 폴더, 점 두 개 `..` 는 한 칸 위 폴더예요.
> 저는 `practice/backup` 폴더에서 `cat ../docs/memo.txt` 로도 열어 보고, 전체 주소로도 열어 봤는데 둘 다 같은 내용이 나왔어요."

➕ 한마디 더 하면 좋은 것
> "그래서 문서에 제 컴퓨터 전체 주소를 그대로 적으면 다른 사람 컴퓨터에선 안 돌아가요. 그래서 명령어에 `$(pwd)` — '지금 위치' 를 자동으로 넣어 주는 표현 — 를 썼어요."

### 1-2. 파일 권한 755, 644 가 뭐예요?

💬 "권한 숫자 755, 644 가 무슨 뜻인지 설명해 주세요."

🗣️
> "파일마다 '누가 무엇을 할 수 있나' 가 정해져 있어요. 할 수 있는 건 세 가지예요. **읽기 r, 쓰기 w, 실행 x**.
> 그리고 사람은 세 부류로 나눠요. **나(소유자), 우리 팀(그룹), 나머지 사람들(기타)**.
> 숫자는 읽기 4, 쓰기 2, 실행 1 을 더해서 만들어요. 그래서 7 은 4+2+1 이라 전부 가능, 5 는 4+1 이라 읽기랑 실행, 4 는 읽기만이에요.
> **755** 는 '나는 다 되고, 남들은 읽고 실행만' — 실행 파일이나 폴더에 써요.
> **644** 는 '나는 읽고 쓰고, 남들은 읽기만' — 일반 파일에 써요.
> 비밀번호 같은 비밀 파일은 **600**, 나만 읽고 쓰게 해요."

🗣️ **꼭 덧붙이세요 — 폴더는 뜻이 달라요**
> "그런데 이게 폴더일 때는 의미가 좀 달라져요.
> 폴더에서 r 은 '안에 뭐 있는지 목록 보기', w 는 '안에 파일 만들고 지우기', x 는 '폴더 안으로 들어가기' 예요.
> 그래서 폴더에 x 가 없으면, 파일 이름을 알아도 못 열어요."

🗣️ **내가 해 본 실험**
> "`hello.sh` 를 644 로 두고 실행하니까 'permission denied' — 권한 없다고 막혔어요. 755 로 바꾸니까 실행됐고요.
> `greeting.txt` 는 444 로 읽기만 되게 하니까 내용 추가가 안 됐고, 644 로 바꾸니까 됐어요.
> `docs` 폴더도 555, 311, 644 로 바꿔 가며 뭐가 되고 안 되는지 다 확인했어요."

### 1-3. 커스텀 이미지는 어떻게 만들었어요?

💬 "Dockerfile 로 이미지 만든 거 설명해 주세요."

🗣️ **먼저 이미지랑 컨테이너 차이부터**
> "**이미지**는 붕어빵 틀이고, **컨테이너**는 그 틀로 찍어 낸 붕어빵이에요.
> 이미지는 '이렇게 실행해라' 하는 설계도라서 안 바뀌고, 컨테이너는 그걸 실제로 실행한 거예요. 틀 하나로 붕어빵 여러 개 찍듯이, 저도 이미지 하나로 컨테이너를 두 개(8080, 8081) 띄웠어요."

🗣️ **어떻게 만들었는지**
> "처음부터 다 만든 게 아니라, 이미 검증된 공식 nginx 이미지를 바탕으로 가져와서 **바꾸고 싶은 것만 위에 얹었어요.**
> nginx 는 웹 페이지를 보여주는 서버 프로그램이고, `alpine` 은 아주 작은 리눅스라서 이미지가 가벼워요."

| Dockerfile 줄 | 말로 하면 |
|---|---|
| `FROM nginx:alpine` | "공식 nginx 를 바탕으로 쓸게요" |
| `LABEL` | "이 이미지 이름이랑 설명 붙여 둔 거예요" |
| `ENV APP_ENV=dev` | "지금 개발용이라는 표시를 넣었어요" |
| `COPY nginx/default.conf` | "설정 파일을 바꿔서 `/health` 주소 추가하고, 어느 컨테이너가 응답했는지 알려주는 표시도 넣었어요" |
| `COPY site/` | "기본 환영 페이지를 제 페이지로 바꿨어요" |
| `HEALTHCHECK` | "살아 있는지 주기적으로 스스로 확인하게 했어요. `docker ps` 에 healthy 라고 떠요" |
| `EXPOSE 80` | "이 컨테이너는 80번 문을 쓴다고 **적어 둔 것**이에요. 실제로 여는 건 아니에요" |

➕ 레이어 질문 나오면
> "Dockerfile 한 줄이 층 하나씩 쌓이는 구조예요. 그래서 다시 빌드할 때 바뀐 줄부터만 새로 만들고, 앞은 재사용해서 빨라요."

### 1-4. 포트 매핑은 왜 필요해요?

💬 "포트 매핑이 왜 필요한가요?"

🗣️
> "컨테이너는 **자기만의 작은 방**처럼 격리돼 있어서, 밖에서 바로 못 들어가요.
> 그래서 `-p 8080:80` 이라고 쓰면 '내 컴퓨터의 8080번 문으로 들어오면, 컨테이너 안의 80번 문으로 연결해 줘' 라는 규칙을 만드는 거예요.
> 아파트로 치면 공동현관 호수가 8080 이고, 그 집 안의 방문이 80 인 거죠.
> 앞 숫자가 **내 컴퓨터**, 뒤 숫자가 **컨테이너 안**이에요."

🗣️ **내가 해 본 것**
> "컨테이너 두 개 다 안에서는 80 을 쓰는데, 바깥 문만 8080, 8081 로 다르게 줬어요. 그러니까 부딪히지 않고 동시에 돌아갔어요.
> 응답에 '누가 응답했는지' 표시가 다르게 나와서 진짜 다른 컨테이너라는 것도 확인했어요."

➕ 보안 얘기 한마디
> "반대로 보너스에서 API 서버는 일부러 바깥 문을 안 열었어요. 꼭 필요한 것만 밖에 공개하는 게 안전하거든요."

### 1-5. 볼륨이 뭐예요?

💬 "Docker 볼륨 설명해 주세요."

🗣️
> "컨테이너 안에 저장한 파일은 **컨테이너를 지우면 같이 사라져요.**
> 볼륨은 컨테이너 **바깥에** Docker 가 따로 관리하는 저장 공간이에요. USB 를 꽂아 쓰는 느낌이라, 컨테이너를 지워도 USB 는 남아 있고, 새 컨테이너에 다시 꽂으면 내용이 그대로 있어요."

🗣️ **내가 해 본 실험 (순서대로 말하기)**
> "볼륨을 하나 만들고 → 컨테이너에 연결해서 파일을 썼어요 → 그 컨테이너를 지웠어요 → 볼륨은 그대로 남아 있었고요 → 새 컨테이너에 같은 볼륨을 붙이니까 아까 쓴 내용이 그대로 나왔어요.
> 비교하려고 볼륨 없이 그냥 컨테이너 안에 쓴 파일은, 지우고 나니까 '파일 없음' 이 떴어요."

💬 "바인드 마운트랑 뭐가 달라요?" 라고 물으면

🗣️
> "바인드 마운트는 **내 컴퓨터의 특정 폴더**를 컨테이너에 그대로 연결하는 거예요. 그래서 제가 컴퓨터에서 파일을 고치면 컨테이너에 **바로** 반영돼요. 개발할 때 편하죠.
> 볼륨은 Docker 가 알아서 관리하는 공간이라, 데이터베이스처럼 **데이터를 오래 보관**할 때 써요.
> 실제로 제 컴퓨터에서 페이지를 v1 에서 v2 로 고쳤더니, 컨테이너 재시작 없이 바로 v2 가 나왔어요.
> 그리고 `:ro` — 읽기 전용 — 으로 연결해서 컨테이너가 제 파일을 실수로 못 바꾸게 했어요."

👉 [README 6.8](../README.md#68-바인드-마운트-호스트-변경-즉시-반영) · [README 6.9](../README.md#69-docker-볼륨-영속성)

### 1-6. Git 이랑 GitHub 차이는요?

💬 "Git 과 GitHub 는 뭐가 달라요?"

🗣️
> "**Git** 은 제 컴퓨터에 깔려 있는 **변경 기록 프로그램**이에요. 인터넷 없어도 돼요. 언제 뭘 바꿨는지 저장(commit)해 두는 거죠.
> **GitHub** 는 그 기록을 **인터넷에 올려 두는 서비스**예요. 백업도 되고, 다른 사람이랑 같이 보고 리뷰도 할 수 있어요.
> 비유하면 Git 은 내 노트의 수정 기록이고, GitHub 는 그 노트를 팀이랑 같이 보는 공유 드라이브예요.
> 둘은 `git push` 로 올리고 `git pull` 로 받아오면서 연결돼요."

### 자주 나오는 질문 — `run -it`, `exec`, `attach` 차이

💬 "컨테이너에 들어가는 방법들 차이가 뭐예요?"

🗣️
> "세 개 다 컨테이너 안으로 들어가는 방법인데, **나올 때** 차이가 커요.
> `docker run -it` 은 새 컨테이너를 만들면서 들어가는 거라, `exit` 하면 컨테이너도 같이 꺼져요.
> `docker attach` 는 이미 돌고 있는 컨테이너의 **본체 프로그램**에 직접 붙는 거라, 여기서 `exit` 해도 컨테이너가 꺼져요.
> `docker exec -it` 은 돌고 있는 컨테이너에 **새 창을 하나 더 여는** 느낌이에요. 그래서 `exit` 해도 그 창만 닫히고 컨테이너는 계속 돌아요.
> 그래서 실제 서비스 중인 컨테이너를 들여다볼 땐 `exec` 를 써야 서비스가 안 멈춰요."

## 3. 트러블슈팅 이야기하기

**말하는 순서**: 무슨 문제였는지 → 왜 그런 것 같았는지 → 어떻게 확인했는지 → 어떻게 해결했는지

### ① OrbStack 이 설치가 안 됐어요

🗣️
> "OrbStack 을 설치하려는데 실행이 안 됐어요.
> 혹시 맥 버전 때문인가 싶어서, 앱 안에 있는 설정 파일을 열어 봤더니 '최소 macOS 14.0' 이라고 적혀 있었어요. 제 맥은 12 였고요.
> 그래서 macOS 12 를 지원하는 마지막 Docker Desktop 버전인 4.41.2 를 깔았고, 자동 업데이트되면 또 안 될 수 있어서 자동 업데이트는 껐어요."

### ② 컨테이너 이름을 출력하려 했는데 제 맥 이름이 나왔어요

🗣️
> "컨테이너 안에서 `hostname` — 컴퓨터 이름 — 을 출력하려고 했는데 이상하게 제 맥 이름이 나왔어요.
> 알고 보니 큰따옴표 `" "` 안에 쓴 `$( )` 는 명령어가 컨테이너로 넘어가기 **전에** 제 맥 터미널이 먼저 바꿔 버리더라고요.
> 그래서 작은따옴표 `' '` 로 감쌌어요. 작은따옴표는 그대로 넘겨 주니까, 컨테이너 안에서 실행돼서 컨테이너 이름이 제대로 나왔어요."

### ③ `docker stop` 이 10초나 걸리고 이상한 숫자 137 이 떴어요

🗣️
> "컨테이너를 멈추는데 매번 10초씩 걸리고, 끝나면 종료 코드가 137 이었어요.
> 찾아보니 `docker stop` 은 먼저 '정리하고 꺼 줘' 하는 신호를 보내고, 10초 안에 안 꺼지면 강제로 꺼 버려요. 그런데 제 컨테이너 안의 bash 가 그 첫 신호를 무시하고 있었던 거예요.
> 137 은 128 + 9 인데, 9 가 '강제 종료' 신호 번호예요. 그러니까 '강제로 꺼졌다' 는 뜻이죠.
> 테스트할 땐 `stop -t 1` 로 기다리는 시간을 1초로 줄였고, 실제 서비스라면 신호를 제대로 받는 프로그램을 쓰거나 `--init` 옵션을 붙이면 돼요."

## 4. 보너스 과제

### 4-1. Compose 기초

💬 "Compose 는 왜 써요?"

🗣️
> "`docker run` 명령이 옵션 붙이다 보면 엄청 길어지잖아요. 그걸 매번 치는 대신 `docker-compose.yml` 이라는 파일에 적어 두고, `docker compose up -d` 한 줄로 실행하는 거예요.
> 좋은 점은 그 파일이 저장소에 남으니까, **다른 사람도 똑같이 실행**할 수 있다는 거예요. 명령어가 문서가 되는 거죠."

👉 [README 7.1](../README.md#71-compose-기초-단일-서비스)

### 4-2. 컨테이너 두 개가 서로 통신

💬 "컨테이너끼리 어떻게 통신했어요?"

🗣️
> "웹 서버(nginx)랑 API 서버(Python) 두 개를 같은 네트워크에 띄웠어요.
> 신기한 게, 서로 부를 때 IP 주소를 몰라도 **서비스 이름**으로 부르면 돼요. 웹에서 `http://api:5000` 이라고 하면 API 서버를 찾아가요. 전화번호 대신 이름으로 연락처 찾는 것처럼요.
> IP 는 컨테이너 새로 띄울 때마다 바뀔 수 있는데, 이름은 안 바뀌니까 이게 편해요.
> 양쪽 방향 다 통신되는 거 확인했어요."

🗣️ **그림 그려 보여주기**
```text
브라우저 ──► localhost:8090 ──► [web: nginx] ──► [api: python :5000]
                                   └──── 같은 내부 네트워크 ────┘
       (밖에서는 web 만 들어올 수 있고, api 는 안에서만 부를 수 있어요)
```

➕ 덧붙이면 좋은 것
> "그리고 API 서버가 완전히 준비된 다음에 웹 서버가 켜지도록 순서도 정해 뒀어요."

👉 [README 7.2](../README.md#72-compose-멀티-컨테이너--서비스-간-통신)

### 4-3. 운영 명령

🗣️
> "띄우고(`up`) → 상태 보고(`ps`) → 로그 보고(`logs`) → 내리고(`down`) → 남은 거 없는지 확인(`ps -a`). 이 순서를 한 바퀴 돌려 봤어요."

👉 [README 7.3](../README.md#73-compose-운영-루틴)

### 4-4. 환경 변수로 설정 바꾸기

💬 "환경 변수는 어떻게 썼어요?"

🗣️
> "포트 번호나 개발/운영 모드 같은 설정값을 코드 안에 박지 않고 `.env` 라는 파일에 따로 빼 놨어요.
> 그래서 코드는 하나도 안 고치고, 실행할 때 `WEB_PORT=8091 API_PORT=7000 APP_MODE=prod` 처럼 값만 바꿔 주면 포트랑 모드가 바뀌어요.
> 이렇게 하면 같은 이미지를 개발용, 운영용으로 그대로 쓸 수 있어요."

💬 "값이 여러 군데 있으면 뭐가 이겨요?"

🗣️
> "실행할 때 직접 준 값이 제일 세고, 그다음 `.env` 파일, 그다음 compose 파일에 적힌 기본값, 마지막이 Dockerfile 이에요. **가까이서 준 값이 이긴다**고 기억하면 돼요."

👉 [README 7.4](../README.md#74-환경-변수로-포트모드-변경)

### 4-5. SSH 키

💬 "SSH 키는 뭐예요?"

🗣️
> "GitHub 에 올릴 때 비밀번호 대신 쓰는 **열쇠 한 쌍**이에요.
> **개인키**는 제 컴퓨터에만 두는 진짜 열쇠고, **공개키**는 GitHub 에 등록해 두는 자물쇠 같은 거예요. 둘이 짝이 맞으면 '아 이 사람 맞구나' 하고 통과시켜 줘요.
> 비밀번호를 인터넷으로 보내지 않아도 되니까 더 안전해요.
> `ssh -T git@github.com` 쳤더니 'Hi ll-0l!' 이라고 인사가 나왔고, 그 방식으로 push 도 성공했어요.
> 개인키는 절대 남한테 주면 안 되고, GitHub 에는 `.pub` 붙은 공개키만 올려요."

👉 [README 7.5](../README.md#75-github-ssh-키)

## 7. 막혔을 때 쓰는 말

모르는 질문이 나와도 괜찮아요. 솔직하게 말하고 **아는 데까지 연결**하면 돼요.

- "그 부분은 정확히는 모르겠는데요, 제가 해 본 것 중에선 ○○ 랑 비슷한 것 같아요."
- "직접 확인해 볼게요." → 명령어를 쳐서 결과를 같이 보기 (말로만 하는 것보다 훨씬 좋아요)
- "README 에 그 결과를 적어 둔 곳이 있어요. 같이 보실래요?"
- "제가 이해한 건 이건데, 혹시 다르게 아시는 게 있으면 알려 주세요."

> 평가자도 같이 배우는 동료예요. **"해 봤다 + 왜 그런지 안다 + 증거가 있다"** 이 세 가지만 보여 주면 충분해요.
